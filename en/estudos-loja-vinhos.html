A wine store database

A small database for a wine store, from the model to a user who only sees what they need.

problem

Build a wine store database, from the model to access control.

my role

I modeled the tables, populated them, wrote the queries and created a user with column-level permissions.

result

3 tables linked by foreign keys, a query with 2 JOINs and a user limited to 40 queries per hour.

The topic

Graded Assignment 2 in Databases asked for a complete database for a wine store: create the tables, populate them, query them and control who can access what. The logic is simple: each wine comes from a winery, and each winery is in a region.

How the assignment was built

  1. 01

    Model in three levels

    Region, Winery and Wine, each with an auto-increment primary key. The winery points to the region and the wine points to the winery, through foreign keys.

  2. 02

    Insert in the right order

    With foreign keys, order matters: first the 5 regions (Vale dos Vinhedos, Napa, Bordeaux, Mendoza and Douro), then the wineries, then the 6 wines. Reverse it and the database refuses.

  3. 03

    Bring it all together in one query

    Two JOINs return the wine's name, year, winery and region in a single row.

  4. 04

    Grant only the access needed

    The sommelier user can read the whole wine table, but only sees the code and name from the winery table. And it's limited to 40 queries per hour.

Professor's feedback

Logical model: the Regiao, Vinicola and Vinho tables were implemented with the correct structure, using auto-increment primary keys and foreign keys that establish the relationships between entities.
Data insertion: the insert statements follow the logical order of dependencies, populating the regions table first, then the wineries and finally the wines, which ensures the database's referential integrity.
Query: the query uses JOINs precisely to retrieve the wine's name, year, winery and region, correctly bringing together the model's three tables.
Access control: the sommelier user was created with the queries-per-hour restriction and given specific SELECT permissions on the wine table and on selected columns of the winery table.
