Banco de uma loja de vinhos

Um banco pequeno pra uma loja de vinhos, do modelo até o usuário que só enxerga o que precisa.

problema

Montar o banco de uma loja de vinhos, do modelo até o controle de acesso.

meu papel

Modelei as tabelas, populei, escrevi as consultas e criei o usuário com permissão por coluna.

resultado

3 tabelas ligadas por chave estrangeira, consulta com 2 JOINs e usuário limitado a 40 consultas por hora.

O tema

A Somativa 2 de Banco de Dados pedia um banco completo pra uma loja de vinhos: criar as tabelas, popular, consultar e controlar quem acessa o quê. A lógica é simples: cada vinho vem de uma vinícola, e cada vinícola fica numa região.

Como o trabalho foi construído

  1. 01

    Modelar em três níveis

    Região, Vinícola e Vinho, cada uma com chave primária de auto incremento. A vinícola aponta pra região e o vinho aponta pra vinícola, por chave estrangeira.

  2. 02

    Inserir na ordem certa

    Com chave estrangeira, a ordem importa: primeiro as 5 regiões (Vale dos Vinhedos, Napa, Bordeaux, Mendoza e Douro), depois as vinícolas, depois os 6 vinhos. Se inverter, o banco recusa.

  3. 03

    Juntar tudo numa consulta

    Dois JOINs trazem o nome do vinho, o ano, a vinícola e a região numa linha só.

  4. 04

    Dar acesso só ao necessário

    O usuário sommelier lê a tabela de vinhos inteira, mas da vinícola só enxerga o código e o nome. E tem limite de 40 consultas por hora.

Devolutiva do professor

Modelo lógico: as tabelas Regiao, Vinicola e Vinho foram implementadas com a estrutura correta, utilizando chaves primárias com auto incremento e chaves estrangeiras que estabelecem as relações entre as entidades.
Inserção de dados: os comandos de inserção seguem a ordem lógica de dependências, populando primeiro a tabela de regiões, depois as vinícolas e, por fim, os vinhos, o que garante a integridade referencial do banco.
Consulta: a consulta utiliza JOINs de forma precisa para recuperar o nome do vinho, o ano, a vinícola e a região, integrando corretamente as três tabelas do modelo.
Controle de acesso: o usuário sommelier foi criado com a restrição de consultas por hora e recebeu as permissões de SELECT específicas para a tabela de vinhos e colunas selecionadas da tabela de vinícolas.

O que aprendi

código

  • PRIMARY KEY AUTO_INCREMENTchave de cada tabela, gerada pelo próprio banco
  • FOREIGN KEYliga a vinícola à região e o vinho à vinícola
  • INSERT INTO … VALUESvárias linhas num comando só, na ordem das dependências
  • JOINjunta as três tabelas numa consulta
  • CREATE USER … MAX_QUERIES_PER_HOURusuário com limite de uso
  • GRANT SELECT (colunas)permissão por tabela e por coluna
